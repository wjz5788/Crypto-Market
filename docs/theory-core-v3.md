# Cognitive Core v3.0：元认知与理论有效性内核

> 2026-10-09 | 状态：理论规范（NOT DEPLOYED / NOT EMPIRICALLY VALIDATED）
>
> 继承：docs/theory-core-v1.md、docs/theory-core-v2.md。
> 原始来源：《万维钢·现代思维工具100讲》v2.0（用户上传的完整 SKILL.md）。
> 工作边界：本阶段只研究理论和评估方法。不扫描币、不修改 Radar、不接市场数据、不授权交易。

## 0. 必须纠正的误区

**拥有一百个思维工具 ≠ 拥有一个正确决策系统。**

- **无免费午餐（3.1）**：任何方法都依赖适用的问题分布、隐含前提和目标。不存在让所有问题都变简单的通用理论。
- **目标函数（9.2）**：现实中「是什么」无法自动推出「应该做什么」。AI 的高效不等于用户真实目标；原则性边界不能被收益替换。
- **内部优化器（9.8）**：即使 AI 表面交出漂亮答案，也可能优化“被认为有用”“打分”“写出更长的理论”。应看实际行为，不看自我表态。
- **预训练与后训练（9.10）**：只有遇到新题、无人提示、跨情境时仍自然选对工具，才说明工具真正被学会。不能只测试写着工具名称的训练样例。

上述四项是本版的**元控制校验**，并非每轮必须把四个工具全调用一次。工具调用仍遵守「1 主、≤3 辅」；这里定义的是系统级守则。

## 1. 分离四类陈述，防止越权

| 层级 | 输入 | 允许输出 | 禁止的偷换 |
|---|---|---|---|
| 描述层（World） | 观察、定义、来源 | 当前有哪些事实、状态与分布 | 一份媒体报道=客观事实 |
| 解释层（Model） | 观察+竞争假说 | 条件性的因果解释及预测 | 相关性=因果性 |
| 认识层（Belief） | 先验+区分性证据 | 更新的信念与不确定范围 | 说得清楚=概率准确 |
| 决策层（Choice） | 信念+用户目标+硬约束+选择集合 | 不行动、试验或行动建议 | 预测可能发生=应该做 |

**约束**：每次从「会发生」走到「应该做」，必须明确用户目标/价值前提、可用选项、机会成本及不可逆风险；缺失时只能描述或保留判断。

## 2. 思维工具选择不使用「关键词触发即执行」

采用「适用域—增量—反证—成本」四维筛选：

1. 识别问题类型与尺度：解释、预测、选择、学习、制度、风险、创新；
2. 列出决定结论的最大未知与最大损失路径；
3. 根据原始 Skill 的【何时调用】筛选候选工具；
4. 根据原始 Skill 的【核心模型 / Agent 程序 / 边界与输出】检查前提；
5. 选出能够**实际改变**问题表示、反例、决策阈值或下一步的一个主工具；
6. 再补最多三个「不同岗位」的工具（机制、估计、定界、反证、造选项、行动）；
7. 做工具消融：删掉主工具，结论/行动完全不变则本次工具属装饰，应移除；
8. 推理收益低于阅读/延迟/注意成本时，停止继续选工具。

低风险机械问题不进入这段流程。高风险问题先检查权利、安全、不可逆损失，再进行收益优化。

### 明确的工具拒用理由（反向路由）

- 没有真实可对照事件和参考类：**不算数值后验**；允许给定性工作假说。
- 不存在可信 Edge 和赔率：**不启动凯利计算**；不靠形式推导制造精确下注量。
- 缺少用户明确目标：**不根据模型偏好自动代定效用函数**。
- 全部证据来自同一消息链：**不将频次误作独立来源数量**。
- 无法定义可检验观察、竞争机制或时间窗：标记「未检验的叙事」，不声称已证明因果。
- 问题仅是机械执行且边界清楚：**不启用 100 讲**。

## 3. 相互竞争的最小科学模型

对重要机制命题 P，必须写：

- H1：我们主要相信的机制，以及导致结果的**中介变量**。
- H0：在没有 H1 时，能否由基准趋势、选择偏差或测量误差解释？
- H2：另一条真正不同、可能解释同一现象的竞争机制。
- E*：一条**尽可能低成本、结果能区分 H1/H0/H2** 的证据。
- K：反例或失效观察。该观察发生时，明确降级或推翻 H1。

默认不假设实验可随机化；不能随机化时承认因果识别局限，尽量使用时序约束、自然实验、可比组或负对照，不把相似性当作因果证明。

### 为什么要用竞争解释

「看见 A、随后看见 B」往往有至少三种解释：A 导致 B、共同原因 C 导致二者、只观察到了被筛选出来的 A/B。选择哪种解释取决于证据区分力，而不是故事优美程度。

## 4. 信念更新的统一协议

定义事件 / 命题、参考类、来源独立性、可观察时间窗后：

- 如有可信参考类与似然信息，可用**后验赔率 = 先验赔率 × 似然比**；
- 独立证据才可在合理前提下更新多次；二手转载、同根统计、共因驱动需合并处理；
- 参考类要记录覆盖/排除标准，以防先看结果后选样本；
- 没有数值依据时采用「倾向上升/下降、低/中/高不确定」并明确原因，**不凭空给 73.6%**；
- 强证据改变**对比方案的排序**后才应优先考虑行动变化；
- 若不同假设对当前证据预测几乎相同，信息增量小，不应大幅更新。

**特别区分**：模型的可信程度不等于结论的真值，也不等于行动适宜性。

## 5. 元认知状态机

- QUESTION：任务目标、价值和尺度还没定。
- MODELED：有可比较假设与可能证伪的预测。
- EVIDENCE_PENDING：关键证据不足，但能指明下一条最有价值信息。
- TENTATIVE：现有证据支持某一解释，但仍存在可改变结论的缺口。
- DECISION_READY：选项、基准、目标、硬约束、风险、证据与下一步都足够明确。
- ABSTAIN：无法可靠判断且不能承担不确定性；可继续低风险搜证，也可暂不行动。
- INVALIDATED：事前规定的失效条件触发；旧结论不再有效。
- CLOSED：问题已结算，进入反馈，不允许事后重写原预测。

这是**认识论状态**，不能和既有 Crypto Radar 的 READY/WATCH/PASS 混为一谈；在后续接入前不建立字段自动映射。

状态转移必须对应一个新证据、约束变化、目标变化或真实结果，禁止只因 AI 写了更多字就升级。

## 6. 主动停止思考

以「信息价值（VOI）」限制无效研究。

当前选择集合为 A，未知证据为 E；只在取得 E **可能改变 A 的排序、改变不可承受风险、或显著改善动作时**继续研究。综合比较：
- 获得证据后带来的期望决策改善（包含错误行动被避免的价值）；
- 获取成本、模型调用成本、注意力成本、时效损耗；
- 窗口过期的机会成本与延迟对判断本身的影响。

停止条件：
1. 新证据不改变选择/边界 → STOP_RESEARCH；
2. 证据价值高而可便宜获得 → NEXT_TEST；
3. 信息昂贵但决定可逆 → SMALL_REVERSIBLE_TRIAL；
4. 不确定性大且决定难以逆转 → ABSTAIN；
5. 没有新事实，仅增加故事 → REUSE_PRIOR_CONCLUSION。

“不行动”是正式选项，不代表推理失败。

## 7. 元控制器也有自己的失败模式

| 目标 | 诱人的代理指标 | 潜在内部优化器偏离 | 保护机制 |
|---|---|---|---|
| 提高判断质量 | 总思维工具调用数 | 每题都套理论 | 消融后无增量则删除 |
| 提高正确率 | 给出肯定答案的比例 | 不承认未知 | 对正确 ABSTAIN 单独计分 |
| 提升研究深度 | 字数和引用数 | 信息堆砌、重复来源 | 独立证据率与 VOI 停止 |
| 减少错误 | 永不行动 | 通过保守回避评估 | 同时评价遗漏的机会成本 |
| 提升预测分数 | 只预测简单事件 | 逃避困难或模糊问题 | 难度分层、完整分母、预注册抽样 |
| 提高用户满意度 | 正反馈 | 迎合当下判断 | 强制竞争解释、盲评与反例 |

元控制器本身不能自动修改自己的评分规则或底线：理论修订要有人审查、有版本、可回滚，并使用事先预留的独立案例复测。

## 8. 纸面推演：一个非 Crypto 示例

**问题**：「产品改版后销售增加 30%，是否证明改版有效？」

- **事实**：改版后观测到销量上涨（前提是统计口径可信）。
- **错误跳跃**：因此改版必然造成上涨。
- **H1**：改版提高实际转化；
- **H0**：季节性增长或渠道推广导致销量增加；
- **H2**：用户结构变化提升销量，改版并无因果作用。
- **主工具**：3.3 颗粒度与因果中介，识别具体转化机制。
- **辅助工具**：3.11 选择偏差，8.4 反馈回路（仅用于解释重复效应，非因果证据）。
- **最便宜的鉴别证据**：看改版前后相同人群渠道分层转化、对照版本；若条件允许再做随机实验。
- **本轮状态**：TENTATIVE / EVIDENCE_PENDING；未证明因果。
- **动作**：暂不把销量上升直接归因为改版；优先建立对照和口径。
- **失效条件**：可比组销量同样上涨，或分层后效应消失时下调 H1。

*这是规则的说明性推演，不是随机化模型性能测试，也不构成实证结果。*

## 9. 版本更新和严格隔离

- 任何新的「理论优于基准」声称，都需要固定输入、匹配推理预算、独立裁判和盲评，具体见 docs/theory-v3-evaluation.md。
- 不能用自己写的规则给自己打满分并宣称通过。
- 不用单一案例决定版本升级；保留失败、未完成、难题、拒答和反例的完整记录。
- 当评估没有显示可靠增量时，优先**简化**理论层，而不是堆更多规则。

**冻结范围**：仅更新 docs/ 下认知文档；不写任何市场扫描或代币分析，不修改现有 Radar/执行文件，不接 API 和钱包。

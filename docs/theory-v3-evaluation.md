## 一、真正的待检验命题

H1：「在相同任务、相同证据、相同模型和可比较的预算下，按《现代思维工具100讲》原始适用域选择工具，能带来比基准更好的**可验证决策质量**。」

H0：「增益只是通用检查清单、更多思考时间、更多字数、额外参考材料或评审偏好造成的；没有可靠增量。」

不要事先认定 H1 正确。任何结果包括 **H0 暂不能拒绝** 或「完整思维工具效果反而更差」都是合格研究发现。

## 二、三组对照，区分理论增量与格式增量

| 组别 | 允许方法 | 目的 |
|---|---|---|
| A：PLAIN | 同一个基础模型、同一任务与证据，常规作答 | 基线 |
| B：CHECKLIST | 同一模型，使用通用的目标/证据/反证/风险/停止检查清单；不带具体100讲条目 | 排除结构化思考本身造成的效果 |
| C：SKILL | 同一模型，按原始完整 Skill 路由，1个主工具+最多3个辅助工具，按选择程序与边界工作 | 检验专门理论体系的边际效果 |

**控制变量**：同一模型版本、温度/采样配置（可用时）、相同原始事实、同样的外部检索能力、相同结算截止点、同样的人类授权规则。

**预算**：至少建立两种成对测试：
- 等「外部资料+推理时间/总token上限」预算，避免 C 靠更多计算获胜；
- 非等预算的自然使用模式，单独计算**质量收益 / 额外成本**，不要与第一类混为一谈。

**防污染**：v2 的 T01–T14 是*开发样例*，不得充当 v3 最终独立测试集。

## 三、独立测试题设计

建议先锁定 **60 个此前未用过的案例**，每个领域 10 题（建议规模，非已实施事实）：

1. 因果识别：干预、时间混杂、自然实验、代理指标；
2. 概率与证据：低基准率、同源证据、假阳性与分布漂移；
3. 风险与决策：正平均但不可逆损失、机会成本、错误的凯利应用；
4. 商业与策略：价值创造/捕获、竞争替代、进入窗口、角色激励；
5. 学习与组织：迁移失败、激励错位、指标优化与内部目标偏离；
6. 元认知与伦理：模糊目标、用户价值冲突、何时应停止/拒答。

至少含：
- 部分问题**不需要任何思维工具**（检验过度激活）；
- 部分问题**无法得到可靠确定答案**（检验合理 ABSTAIN）；
- 部分问题有**少见但重要的反例**（检验尾部保护）；
- 部分问题的信息**真实但与行动无关**（检验 VOI）；
- 部分问题安排**反证后续轮次**（检验是否及时改判）。

编题者不得只把 v2 已出现的题换词。优先使用新颖事实结构与清晰参考答案的案例，困难案例需要多人核对评审标准。

## 四、预注册裁判：先规定，再看答案

### 主要结果指标（不可在看到数据后任意更换）

**P1：关键判断错误率**：把相关说成因果、把传闻说成已证实、忽视明确约束、捏造精确概率等。按每例是否出现任意一项关键错误记录二元事件。

**P2：可验证决策质量**（0–4）：
- 0：错误目标或违法/高危/错误因果；
- 1：识别问题但混淆关键证据；
- 2：给出合理方向，但缺关键反证或行动边界；
- 3：目标、基准、证据、反例和行动合理；
- 4：在 3 的基础上，提供低成本区分性测试、明示停止/更新条件并处理时间尺度。

### 次要指标

- **S1 过度自信**：结论确定性是否超过证据强度；
- **S2 不必要拒答**：存在安全可逆行动但模型无谓 ABSTAIN；
- **S3 工具装饰率**：主工具消融后，实质判断没变化；
- **S4 信息效率**：输出相同质量消耗的总token、耗时和额外资料；
- **S5 覆盖广度**：跨不同题型保持表现，避免只改善某一类题；
- **S6 预测校准**：仅对真正定义好、可结算的概率问题计算 Brier 等概率评分；不存在数字预测的不参与。

**权衡**：不可通过「所有题一律 ABSTAIN」刷 P1；必须同时看 P2 与 S2，并披露未回答率。

### 人工判分

- 每道题 A/B/C 采用随机呈现顺序，去掉组别/工具名；
- 至少两位评审独立按预注册规则打分，冲突需记录并由第三方裁决；
- 保留两位原始分、分歧率和最终分，不以讨论后的分数替代原始记录；
- 对 factual correctness 应优先采用明确答案、原始数据或可验证实验材料；不要让模型自评自己的能力。

## 五、如何解释结果

- 主要比较 C 对 B（是否有**具体理论**增量），再看 B 对 A（是否只需要**基本结构化**）。
- 逐题做**配对差异**分析，报告改善、持平、恶化比例及不确定区间；不因单个样例成功宣称整体有效。
- 同时分层报告6类任务：若 C 只在某类有效，应给出适用域，禁止推广为「所有问题都更强」。
- 检查 C 的错误减少是否以大量 ABSTAIN、更多计算或过长报告为代价。
- 观察一组消融：C 去掉「原版工具正文」而只保留结构协议；如果结果接近 C，则增益主要来自流程，不是100条特定知识。
- 最少重复几轮由可用预算决定，但每组样例的采样方式、模型版本、轮数需记录；不能只留下最好一次的答案。

**建议的初始工程评价门槛**：在60例独立盲评中，C 相较 B 的关键错误率改善和质量提高应同时有一致方向、不是靠过度拒答、在多数任务分组中保持稳定，并能解释成本。这里不预设一个能保证统计显著的百分比；60例只算初步证据，区间宽时应承认不确定性并扩大样本。

## 七、最小演示与真正实验的界限

可以人工推演单个示例，检查「状态机是否自洽」。
但是：
- 人工演示 ≠ 实际模型实验；
- 写出评估代码 ≠ 已验证改善；
- 理论覆盖100工具 ≠ AI 能无提示正确调用100工具；
- 对一次测试表现优秀 ≠ 可迁移到真实世界；
- 正确预测 ≠ 合适行动（仍需用户目标、风险边界与授权）。

## 八、如果实验结果不好，如何修订理论

错误类型分六类：
1. **ROUTING**：主工具选择错、误把小任务升格复杂任务。
2. **GROUNDING**：事实、来源独立性或测量时间有误。
3. **MODEL**：混杂因子/机制/参考类选择错误。
4. **UNCERTAINTY**：不够谨慎、过度谨慎或伪精确。
5. **VALUE_ALIGNMENT**：把效率、收益或模型偏好偷换成用户目标。
6. **UPDATE_FAILURE**：反证已出现但不愿改判。

先修引起错误的单个环节，记录版本号与保留案例；对新版本使用新的封存测试集重测。不得因为 C 没赢就临时换一套评分规则。
